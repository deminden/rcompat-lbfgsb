# Provenance

`rcompat-lbfgsb` is intended to be an MIT-licensed, clean-room Rust
implementation of the user-visible behavior of R's
`stats::optim(..., method = "L-BFGS-B")`.

Provenance is part of this crate's architecture. Compatibility decisions should
be traceable to public behavior, public documentation, generated fixtures, or
permissively licensed dependencies. They should not be traced to copied,
translated, or paraphrased GPL/R implementation source.

## Clean-room boundary

- No R source code, R C source, R Fortran source, or GPL-derived optimizer code
  may be copied, translated, paraphrased, or used as an implementation source.
- R may be run externally during development to generate input/output parity
  fixtures. The crate must not call, link, shell out to, embed, or depend on R at
  runtime.
- Normal `cargo test` must not require R to be installed.
- Public documentation and black-box behavior are acceptable references.
- If upstream optimizer repositories are inspected, store them under the ignored
  `external/` directory.

## Inspection-only upstream material

For license review or behavioral background, a maintainer may clone or copy
upstream repositories into `external/`. This material is not part of the crate,
must not be packaged, and must not be used as source text for Rust
implementation.

The repository at <https://github.com/jonathanschilling/L-BFGS-B> may be useful
for inspection because it collects L-BFGS-B source history, but code from it
must not be copied directly into this crate.

R source snapshots or tarballs may also be kept under `external/` for
inspection-only behavior archaeology. Any compatibility change informed by such
inspection must still be validated through public behavior, generated R traces,
or parity fixtures, and no R source text may be copied, translated, or
paraphrased into the Rust implementation.

## Accepted implementation inputs

- Public R documentation for `optim` and its controls.
- Parity and trace fixtures generated by running R externally during
  development.
- Small committed fixture subsets copied from ignored local real-data fixtures
  when their source, selection rule, and generated optimizer behavior are
  documented.
- Independently written Rust code in this repository.
- Permissively licensed dependencies after their licenses have been verified.

## Pinned validation stack

The current reference generation and final validation were completed on
2026-07-22 with:

- R 4.6.1 (2026-06-24), platform `x86_64-conda-linux-gnu`;
- OpenBLAS 0.3.32 as BLAS and LAPACK, forced to one thread;
- Bioconductor 3.23 and DESeq2 1.52.0 for the scientific fixture environment;
- `%.17g` serialization with binary64 round-trip checks;
- rustc/cargo 1.96.0, LLVM 22.1.2, host `x86_64-unknown-linux-gnu`.

The R-side stack is an external fixture oracle, not a runtime dependency. The
exact-version claim is evidence for this pinned stack; other CPUs, math
libraries, compilers, or callback expression groupings can legitimately expose
new floating-point paths and should be validated with new fixtures.

## Real-data fixture policy

`data/` is intentionally ignored and excluded from packaging. Small, reviewed
subsets may be copied into `fixtures/` when they are needed for compatibility
tests and are not implementation source.

`fixtures/deseq_airway/` adds a self-contained published-count source that does
not require the ignored historical bundle. `scripts/generate_airway_fixtures.R`
loads airway 1.32.0 (GEO GSE52778; Himes et al., 2014,
<https://doi.org/10.1371/journal.pone.0099625>), estimates size factors and
dispersions through the public DESeq2 API, and selects 14 distinct count
profiles by expression depth, treatment imbalance, and sparsity. It captures
28 paired/unpaired public `nbinomWaldTest` fits through
`scripts/baseline_deseq2_r461.R`. A single IRLS iteration deliberately triggers
the actual fallback; the nested optimizer retains its default controls. The
JSON records its R/DESeq2 versions and oracle platform. This new oracle runs
on `aarch64-apple-darwin20.0.0`; it is not silently mixed with the older pinned
x86 reference. No R or DESeq2 implementation text is included, and no R
runtime dependency is introduced.

The current `fixtures/deseq_real_subset/` data was selected from `data/` by
`scripts/generate_r_fixtures.R`. It contains a compact set of numeric DESeq
workflow outputs and R `optim` results for an independently written standard
negative-binomial GLM objective. It does not contain copied DESeq2, R, C, or
Fortran implementation code.

The current `fixtures/deseq_hard_real_subset/` data was selected from the
ignored `data/lbfgsb_hard_real_2026-06-01/` bundle by
`scripts/generate_hard_real_fixtures.R`. It keeps six hard numeric optimizer
cases per completed contrast and stores generated R `optim` outputs for an
independently written negative-binomial GLM objective using DESeq2's log2-scale
coefficient convention. The generator replays objective-only
`optim(method = "L-BFGS-B")`, matching DESeq2's GLM fallback optimizer shape.
The normal test uses these fixtures as a compact behavioral guard. On the pinned
R 4.6.1 reference replay, all 48 cases have exact parameters, values,
optimizer-level counts, convergence codes, and messages.

The ignored `data/lbfgsb_hard_real_2026-06-01/` bundle is also used for local
trace investigation through `scripts/trace_hard_real_case.R`. That helper
invokes R's own `optim(method = "L-BFGS-B")` on the independent objective and
can enable R optimizer trace output with `HARD_REAL_OPTIM_TRACE`; these traces
are inspection artifacts only and are not copied into the implementation.
Reference checks use the dedicated `rsfgsea-r461` Conda environment, verified
on 2026-07-22 with R 4.6.1, Bioconductor 3.23, and DESeq2 1.52.0. The separate
`rsfgsea-r460` environment remains preserved for direct R 4.6.0 comparisons.

The ignored `data/lbfgsb_synthetic_stress_2026-07-22/` bundle was regenerated
by `scripts/generate_lbfgsb_synthetic_stress_fixtures.R` in the companion
`rsdeseq2` project, using R 4.6.1 and one OpenBLAS thread. Double-valued fields
are serialized with 17 significant digits and reread by the generator, which
requires bit-exact IEEE-754 round trips before completing. Its manifest records
the R platform, BLAS/LAPACK libraries, thread setting, and numeric format. A
full external R
replay exactly reproduced all 512 saved parameter vectors, objective values,
and optimizer counts. Every payload file is byte-identical to the preserved
R 4.6.0 bundle at `data/lbfgsb_synthetic_stress_2026-07-20/`; only the manifest
version and environment path differ. The earlier R 4.3.3 bundle also remains
preserved at `data/lbfgsb_synthetic_stress_2026-06-06/`. These oracle
generations are not mixed and remain excluded from normal packaging.

The R `optim` fixture set also includes small raw objective-call trace fixtures
generated by `scripts/generate_r_fixtures.R`. These traces record parameter
vectors passed to an independent test objective and are used to guard
user-visible wrapper behavior such as finite-difference stencil order near
bounds. The 63 standard fixtures and the DESeq real and hard-real optimizer
replays were regenerated on 2026-07-22 with the pinned R 4.6.1 environment.
Their generators serialize doubles with 17 significant digits and obtain the R
version and platform directly from the running process. Relative to R 4.6.0,
all 65 committed JSON changes are metadata-only.

The `line_search_refresh_sin_quad` fixture is a synthetic black-box R behavior
case generated by the same script. Its objective is an independently written
finite-box sinusoidal quadratic. Running R `optim(method = "L-BFGS-B")` with
high trace verbosity shows a line-search memory refresh before successful
`factr` convergence; the committed fixture stores only the generated inputs and
public optimizer result, not R implementation text. The fixture was regenerated
with R 4.6.1 on 2026-07-22; its numeric result was unchanged. A separate R 4.6.0
black-box audit compared hexadecimal doubles for all 220 raw objective calls.
That replay established the exact expression grouping, the repeated
rounded-to-the-same-point trials during the failed search, and the best-point
restoration on the successful retry without inspecting optimizer source.

The `pgtol_near_upper_uses_bound_distance` fixture is another synthetic
black-box R behavior case generated from an independent one-dimensional linear
objective. It records R's projected-gradient stopping norm near a finite bound:
the raw gradient is large, but the projected component is capped by the
remaining distance to the upper bound, so R reports initial `pgtol`
convergence.

The coherent compact Cauchy/subspace state, exact-bound full-step target copy,
and More-Thuente arithmetic are independent Rust implementations of public
algorithmic formulas and black-box-observed operation grouping. They are used
for the default multidimensional finite-box path with either supplied gradients
or finite differences. Objective-only bound classification and fallback
direction projection retain their separately validated activity rules. No R,
C, or Fortran implementation text was copied or paraphrased.

The final R 4.6.1 validation is bit-exact for all 68 committed DESeq
supplied-gradient cases, all 48 committed hard-real objective-only cases, and
all 512 ignored synthetic stress cases, including optimizer counts and public
status. The DESeq test replay models the recorded platform's extended-precision
`sum()` and permissively licensed OpenBLAS DGEMV reduction shapes so callback
arithmetic is not mistaken for optimizer drift. No runtime dependency on R or
OpenBLAS was added.

## macOS ARM DESeq2 precision profile

The optional `arm-fma` arithmetic profile was validated against R 4.6.1,
DESeq2 1.52.0 and OpenBLAS 0.3.34 Vortex on macOS ARM. Public BLAS dot-product
probes established sequential fused short-dot reduction. An independently
written C multiplication/addition probe, built using the installed R
environment's Clang 23.1.3 and configured CFLAGS, demonstrated scalar `fmadd`
contraction. Only our own probe's assembly was inspected. No R implementation
source or compiled implementation was used as a source for these changes.

The callback in `examples/support/deseq2_objective.rs` independently uses
[Loader's published saddlepoint formulas](https://people.math.ethz.ch/~maechler/doc/CLoader-dbinom-2002.pdf)
and the mathematical log-gamma power series obtained by integrating the
[NIST DLMF psi series](https://dlmf.nist.gov/5.7#E4). Integer Stirling and zeta
constants are mathematical values, not fitted gene-specific constants.
Gamma recurrence yields the positive remainder increment
`sum(t^(2k)/(2k+1))`, with `t=1/(2z+1)`. Our mathematical implementation
does not use the paper's code appendix, R/DESeq2 source, or a runtime oracle.

`fixtures/deseq2_precision_baseline.json` freezes per-fit coefficient errors
from the previous naive full-NB/Gaussian-prior Rust callback using default
optimizer arithmetic, compared with the captured actual package fits. It is
a previous Rust accuracy baseline, not another R oracle. Across the 74 fits,
the measured worst coefficient errors are `0.00139872` (old 46; 10.9x improvement)
and `3.76263e-6` (published 28; 217,578x improvement), in both debug and release.
The largest observed individual error increase is `1.18e-7`. Legacy x86 fixture assertions are
preserved; the ARM mode is opt-in and tested against its own oracle.

## Dependency policy

Runtime dependencies must be permissively licensed and compatible with this
crate's MIT license target. If an optimizer backend is added, it must be isolated
behind the crate's backend abstraction so that R-compatible semantics remain in
this wrapper layer.

License checks and fixture provenance should be updated whenever a new backend,
dependency, or fixture source is added.
